# Соседи — MVP сервиса поиска сожителей

Веб-сервис для поиска соседей по квартире (Россия, затем СНГ). Идея — как у Flatmates.com.au,
механика знакомства — взаимные свайпы, как в Tinder. Продукт на этапе MVP **полностью бесплатный**:
никаких лимитов на свайпы и платных функций.

## Как это работает

1. Пользователь регистрируется и заполняет анкету: кто он, бюджет, районы, образ жизни.
2. **Ищущий** свайпает объявления о комнатах в своём городе.
3. **Владелец** публикует объявление и свайпает анкеты ищущих для этой комнаты.
   Один человек может быть и тем и другим.
4. Когда обе стороны лайкнули друг друга по одной паре «комната + человек» — **мэтч**, открывается чат.
5. Точный адрес комнаты виден только после мэтча. Жалобы разбирают модераторы в админке.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Бэкенд | Python 3.12, Django 5.2 (LTS) | Админка для модерации из коробки, ORM, авторизация |
| Фронтенд | Шаблоны Django + HTMX | Свайпы и чат без перезагрузки, без отдельного SPA; SEO-готовность |
| База | SQLite локально, PostgreSQL в Docker/проде | Ноль настройки для разработки, надёжность в проде |
| Статика | WhiteNoise | Не нужен отдельный nginx на старте |
| Сервер | gunicorn в Docker | Один образ для staging и прода |
| Качество | pytest, ruff, GitHub Actions | Тесты и линтер на каждый push |

## Структура (модульный монолит)

```
config/            настройки, корневые адреса
apps/accounts/     пользователь (вход по email) и анкета
apps/geo/          города (Москва активна, остальные включаются в админке)
apps/listings/     объявления о комнатах и фото
apps/matching/     свайпы, мэтчи, лента со скорингом   ← ядро продукта (services.py)
apps/messaging/    чат внутри мэтча (HTMX-поллинг раз в 5 с)
apps/moderation/   жалобы, автоскрытие после N жалоб от разных людей
templates/         HTML-шаблоны
tests/             тесты логики и страниц
```

Бизнес-логика вынесена в `services.py` модулей, чтобы её было легко тестировать
и переиспользовать в будущем API для мобильного приложения.

## Быстрый старт (локально, без Docker)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python manage.py migrate
python manage.py seed_demo        # демо-данные: 6 ищущих, 5 комнат, пара мэтчей
python manage.py runserver
```

Откройте http://127.0.0.1:8000. Пароль всех демо-аккаунтов — `demo12345`:

- `seeker1@sosedi.local` — у Анны уже есть мэтч и чат;
- `seeker5@sosedi.local` — Ксению уже лайкнул владелец, лайк сразу даст мэтч;
- `owner2@sosedi.local` — на его комнату есть входящий лайк;
- `admin@sosedi.local` — модератор, админка на http://127.0.0.1:8000/admin/.

## Запуск в Docker (как в проде, с PostgreSQL)

```bash
cp .env.example .env              # поменяйте DJANGO_SECRET_KEY
docker compose up --build
docker compose exec web python manage.py seed_demo
```

## Тесты и проверки

```bash
pytest                            # 36 тестов: мэтчи, ленты, права доступа, чат, жалобы
ruff check . && ruff format --check .
python manage.py makemigrations --check --dry-run
```

То же самое автоматически запускает GitHub Actions (`.github/workflows/ci.yml`) на PostgreSQL.

## Настройки продукта (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LISTINGS_PREMODERATION` | `0` | `1` — новые объявления видны только после одобрения модератором |
| `FEED_RESURFACE_PASSED_AFTER_DAYS` | `14` | Через сколько дней пропущенная карточка снова появится в ленте |
| `AUTO_HIDE_AFTER_REPORTS` | `3` | Сколько жалоб от разных людей скрывают анкету до проверки |

## Что дальше (после MVP)

- Монетизация (лимиты, Boost, «кто меня лайкнул») — точка расширения: `apps/matching/services.py::record_swipe`.
