# Соседи — MVP сервиса поиска сожителей

Веб-сервис для поиска соседей по квартире (Россия, затем СНГ). Идея — как у Flatmates.com.au,
механика знакомства — взаимные свайпы, как в Tinder. Продукт на этапе MVP **полностью бесплатный**:
никаких лимитов на свайпы и платных функций.

## Закрытый тест (включён по умолчанию)

- **Регистрация только по приглашениям.** Админка → «Приглашения» → «Добавить» → впишите, для кого →
  сохраните и скопируйте ссылку. Или из командной строки: `python manage.py create_invites 5 --note "друзья"`.
  Каждая ссылка одноразовая, неиспользованную можно отозвать.
- **Сайт скрыт от поисковиков:** robots.txt, заголовок `X-Robots-Tag` и meta noindex.
- Для публичного запуска: `INVITE_ONLY=0` и `SITE_NOINDEX=0`. В проде задайте `SITE_URL=https://ваш-домен`,
  иначе ссылки-приглашения будут вести на localhost.

## Безопасность

- Пароли — Argon2. Вход блокируется на 15 минут после 5 неудачных попыток (по email и по IP).
- Защитные пороги от ботов: 300 свайпов в час и 40 сообщений за 10 минут — живой человек их не заметит.
- Фото при загрузке пересобираются: уменьшаются до 1600 px, стираются все метаданные, включая GPS,
  исходное имя файла не сохраняется, «не картинки» отклоняются.
- Блокировка собеседника: из меню «⋯» в чате или вместе с жалобой. Чат исчезает у обоих, люди пропадают
  из лент друг друга, новый мэтч невозможен.
- Удаление аккаунта (Анкета → «Удалить аккаунт», с подтверждением паролем) стирает анкету, объявления,
  фото с диска, мэтчи и переписку.

## Как это работает

1. Пользователь регистрируется и заполняет анкету: кто он, бюджет, районы, образ жизни.
2. **Ищущий** свайпает объявления о комнатах в своём городе.
3. **Владелец** публикует объявление и свайпает анкеты ищущих для этой комнаты.
   Один человек может быть и тем и другим.
4. Когда обе стороны лайкнули друг друга по одной паре «комната + человек» — **мэтч**, открывается чат.
5. Точный адрес комнаты виден только после мэтча. Жалобы разбирают модераторы в админке.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Бэкенд | Python 3.12, Django 5.2 (LTS) | Админка для модерации из коробки, ORM, авторизация |
| Фронтенд | Шаблоны Django + HTMX + свой swipe.js | Свайп пальцем и чат без перезагрузки, без отдельного SPA |
| Дизайн | Стиль «Зелёный трамвай», шрифты Unbounded и Onest (лежат в проекте) | См. макеты «Соседи — дизайн» |
| База | SQLite локально, PostgreSQL в Docker/проде | Ноль настройки для разработки, надёжность в проде |
| Статика | WhiteNoise | Не нужен отдельный nginx на старте |
| Сервер | gunicorn в Docker | Один образ для staging и прода |
| Качество | pytest, ruff, GitHub Actions | Тесты и линтер на каждый push |

## Структура (модульный монолит)

```
config/            настройки, корневые адреса
apps/accounts/     пользователь (вход по email) и анкета
apps/geo/          города (Москва активна, остальные включаются в админке)
apps/listings/     объявления о комнатах и фото
apps/matching/     свайпы, мэтчи, лента со скорингом   ← ядро продукта (services.py)
apps/messaging/    чат внутри мэтча (HTMX-поллинг раз в 5 с)
apps/moderation/   жалобы, автоскрытие после N жалоб от разных людей
templates/         HTML-шаблоны
tests/             тесты логики и страниц
```

Бизнес-логика вынесена в `services.py` модулей, чтобы её было легко тестировать
и переиспользовать в будущем API для мобильного приложения.

## Запуск на Mac в один клик

1. Установите Python с [python.org](https://www.python.org/downloads/macos/) (если ещё не стоит).
2. Распакуйте архив и дважды щёлкните `start.command`.
3. Первый запуск занимает 1–3 минуты, потом сайт сам откроется в браузере.

Если macOS пишет, что файл «от неустановленного разработчика»: откройте
«Системные настройки → Конфиденциальность и безопасность», внизу нажмите «Всё равно открыть».
Остановить сайт — закрыть окно Терминала. Сбросить демо-данные — удалить `db.sqlite3` и запустить снова.

## Быстрый старт (локально, без Docker)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python manage.py migrate
python manage.py seed_demo        # демо-данные: 6 ищущих, 5 комнат, пара мэтчей, 2 приглашения
python manage.py runserver
```

Откройте http://127.0.0.1:8000. Пароль всех демо-аккаунтов — `demo12345`:

- `seeker1@sosedi.local` — у Анны уже есть мэтч и чат;
- `seeker5@sosedi.local` — Ксению уже лайкнул владелец, лайк сразу даст мэтч;
- `owner2@sosedi.local` — на его комнату есть входящий лайк;
- `admin@sosedi.local` — модератор, админка на http://127.0.0.1:8000/admin/.

## Запуск в Docker (как в проде, с PostgreSQL)

```bash
cp .env.example .env              # поменяйте DJANGO_SECRET_KEY
docker compose up --build
docker compose exec web python manage.py seed_demo
```

## Тесты и проверки

```bash
pytest                            # 59 тестов: мэтчи, ленты, права доступа, чат, жалобы, приглашения, защита
ruff check . && ruff format --check .
python manage.py makemigrations --check --dry-run
```

То же самое автоматически запускает GitHub Actions (`.github/workflows/ci.yml`) на PostgreSQL.

## Настройки продукта (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LISTINGS_PREMODERATION` | `0` | `1` — новые объявления видны только после одобрения модератором |
| `FEED_RESURFACE_PASSED_AFTER_DAYS` | `14` | Через сколько дней пропущенная карточка снова появится в ленте |
| `AUTO_HIDE_AFTER_REPORTS` | `3` | Сколько жалоб от разных людей скрывают анкету до проверки |

## Выкладка на Amvera (основной вариант)

Настройки хостинга лежат в `amvera.yml`: сборка из `Dockerfile`, порт 8000, постоянный диск в `/data`.
При каждом старте контейнер сам применяет миграции и создаёт администратора (`docker-entrypoint.sh`).

1. **База.** «PostgreSQL» → «Создать базу данных», тариф «Начальный» или выше. Имя базы и пользователя
   любые, кроме `postgres`. Внутренний адрес для приложения: `amvera-<логин>-cnpg-<проект>-rw`
   (точное значение — на вкладке «Инфо» базы).
2. **Приложение.** «Приложения» → «Создать», тариф «Начальный» или выше.
3. **Домен.** Вкладка «Домены» → «Добавить доменное имя» → «Бесплатный домен Амвера», тип HTTPS.
4. **Переменные** (вкладка «Переменные», пароли и ключи — как «секрет»):

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | `postgres://пользователь:пароль@amvera-<логин>-cnpg-<проект>-rw:5432/имя_базы` |
   | `DJANGO_SECRET_KEY` | длинная случайная строка |
   | `DJANGO_DEBUG` | `0` |
   | `DJANGO_ALLOWED_HOSTS` | домен из шага 3 без `https://` |
   | `DJANGO_CSRF_TRUSTED_ORIGINS` | тот же домен с `https://` |
   | `SITE_URL` | тот же домен с `https://` |
   | `DJANGO_SECURE_SSL_REDIRECT` | `0` — https обеспечивает сам Amvera |
   | `DJANGO_MEDIA_ROOT` | `/data/media` — фото на постоянном диске, не пропадают при обновлении |
   | `DJANGO_SUPERUSER_EMAIL`, `DJANGO_SUPERUSER_PASSWORD` | администратор |

5. **Код из GitHub.** Вкладка «Репозиторий» → GitHub → ветка `main`, придумать секрет, скопировать адрес.
   В GitHub: репозиторий → Settings → Webhooks → Add webhook: адрес из Amvera, Content type
   `application/json`, тот же секрет, событие Push. Нужен также токен GitHub (classic, право `repo`),
   его вставляют на той же вкладке Amvera. После этого каждый push в `main` выкатывается сам.
6. **Проверка:** `https://домен/healthz/` отвечает `ok`, админка — `https://домен/admin/`.

## Выкладка на Timeweb Cloud (App Platform, запасной вариант)

Приложение собирается из `Dockerfile` в корне репозитория. При каждом старте контейнер сам
применяет миграции, а статику раздаёт WhiteNoise, поэтому отдельный nginx не нужен.

1. **База.** В панели Timeweb создайте облачную базу PostgreSQL 16 в том же регионе и скопируйте
   строку подключения вида `postgres://пользователь:пароль@хост:5432/имя_базы`.
2. **Приложение.** App Platform → «Создать» → Docker / Dockerfile → подключите GitHub и выберите
   репозиторий `sosedi`, ветку `main`. Включите автодеплой, чтобы каждый push в `main` выкатывался сам.
3. **Проверка здоровья:** путь `/healthz/` (порт 8000 приложение объявляет само через `EXPOSE`).
4. **Переменные окружения** (остальные можно не трогать, см. `.env.example`):

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения из шага 1 |
   | `DJANGO_SECRET_KEY` | длинная случайная строка: `python -c "import secrets; print(secrets.token_urlsafe(50))"` |
   | `DJANGO_DEBUG` | `0` |
   | `DJANGO_ALLOWED_HOSTS` | домен приложения без `https://`, например технический домен от Timeweb |
   | `DJANGO_CSRF_TRUSTED_ORIGINS` | тот же домен с `https://` |
   | `SITE_URL` | тот же домен с `https://` — из него собираются ссылки-приглашения |
   | `DJANGO_SUPERUSER_EMAIL`, `DJANGO_SUPERUSER_PASSWORD` | администратор, создаётся при первом старте |

   Сначала задеплойте с любым доменом, посмотрите, какой технический домен выдал Timeweb, впишите его
   в три переменные выше и перезапустите. Свой домен потом добавляется туда же через запятую.
5. **После запуска:** войдите в `/admin/` под администратором и создайте приглашения
   («Приглашения» → «Добавить»). Демо-данные на сервере не загружаются.

**Фото — в хранилище S3**, иначе они пропадают при каждом редеплое:

1. Timeweb Cloud → «Хранилище S3» → «Создать бакет», тип **приватный**, тот же регион.
2. В панели бакета, вкладка «Дашборд», скопируйте S3 Access Key и S3 Secret Access Key.
3. Добавьте переменные приложения: `S3_BUCKET` (имя бакета), `S3_ACCESS_KEY`, `S3_SECRET_KEY`.
   Адрес `https://s3.twcstorage.ru` и регион `ru-1` уже прописаны по умолчанию.
4. Сохраните — после деплоя новые фото пойдут в бакет. Сайт показывает их по временным
   подписанным ссылкам (6 часов), прямые ссылки на файлы в приватном бакете не открываются.
